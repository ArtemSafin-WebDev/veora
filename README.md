# Veora — базовая сборка многостраничного сайта

`/search.html` — пустая страница поиска по десктопному и мобильному макетам. Данные находятся в `src/data/pages/search.json`, секция — в `src/sections/search/`, общая форма — в `src/components/search-form/`. Форма нативно отправляет GET-параметр `q` на `/search-results.html`; адрес, метод, имя параметра, значение и подписи задаются в `search.form`. Клиентский код восстанавливает запрос из URL. При подключении Битрикс замените адрес обработчика и передавайте текущий запрос в `value`. Общие шапка и футер переиспользуются. Сборка создаёт `dist/search.html`.

`/search-results.html` — поисковая выдача по макетам 1366 и 360. Использует ту же секцию поиска с вариантом `results` и тот же БЭМ-компонент `search-form`. Данные — `src/data/pages/search-results.json`, секция — `src/sections/search-results/`. `searchResults.items` содержит заголовки, описания, категории и ссылки; каждая карточка `search-result-card` целиком является одной ссылкой, а «Подробнее» — вложенный неинтерактивный `span` общего компонента `button`. Пока деталки из макета не созданы, ссылки ведут на существующие каталоги соответствующих разделов. Категории `search-categories` фильтруют статические карточки, сохраняют параметр `category` и запрос в URL, поддерживают историю браузера и пустое состояние. Счётчики оставлены по макету и передаются отдельно в `categories.items[].count`. Для Битрикс заполните выдачу, счётчики и реальные адреса из серверного поиска; текущие четыре карточки — статическое наполнение, поиск по содержимому сайта не выполняется. Сборка создаёт `dist/search-results.html`.

Vite собирает отдельные HTML-страницы, TypeScript и SCSS. Nunjucks даёт страницам наследовать общий layout через `extends` и переопределять его блоки. Шрифт Inter поставляется локально через Fontsource и входит в сборку без запросов к Google Fonts. Результат — статические файлы, которые можно подготовить к переносу в сайты Битрикс24.

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес, который выведет Vite. Готовую сборку создаёт `npm run build` в папке `dist/`. Для её локального просмотра — `npm run preview`.

## Структура

- `index.html` — главная страница.
- `about/index.html` — пример внутренней страницы.
- `src/templates/layout.njk` — общий HTML-каркас с блоком `content`.
- `src/components/` — переиспользуемые БЭМ-компоненты; у каждого свой `.njk` и `.scss`.
- `src/sections/` — секции страниц как самостоятельные БЭМ-блоки; у каждой свой `.njk` и `.scss`.
- `src/data/site.json` — общие данные сайта; `src/data/pages/` — данные отдельных страниц.
- `src/styles/main.scss` — точка подключения SCSS компонентов и секций; `_base.scss` и `_tokens.scss` — базовые стили и переменные.
- `src/main.ts` — клиентский TypeScript.
- `vite.config.mjs` — поиск HTML-страниц, подключение шаблонов и загрузка JSON-данных.
- `AGENTS.md` — правила вёрстки, включая `1rem = 10px` и медиавыражения в пикселях.

## Новая страница

Создайте `contacts.html` в корне проекта рядом с `index.html` с наследованием layout и подключением секции:

```html
{% extends "layout.njk" %}
{% block content %}
  {% include "sections/contacts/contacts.njk" %}
{% endblock %}
```

Создайте данные `src/data/pages/contacts.json` с `title`, `description`, `activePage` и данными секции. Добавьте секцию в `src/sections/contacts/` с файлами `contacts.njk` и `_contacts.scss`; подключите SCSS в `src/styles/main.scss`. Для ссылки в навигации дополните `src/data/site.json`.

Страница будет доступна по `/contacts.html` и автоматически попадёт в `dist/contacts.html`. Путь к JSON повторяет путь к HTML-странице внутри `src/data/pages/`.

Файлы из `public/` (если папка нужна) Vite копирует в сборку без обработки. Импортируемые из TypeScript и SCSS ресурсы Vite обрабатывает и хеширует.

## Страница услуг

`/services.html` — каталог по desktop-макету 1366 и мобильному макету 360. Данные находятся в `src/data/pages/services.json`. В сборке страница доступна в `dist/services.html`.

- `breadcrumbs(items, label)` из `src/components/breadcrumbs/breadcrumbs.njk` — самостоятельный БЭМ-блок хлебных крошек без дополнительных классов секций. Принимает массив `{ label, href? }` и название навигации для `aria-label`. Элемент без `href` обозначает текущую страницу; пустой массив не выводит навигацию. Цвет наследуется от окружения.
- `pageBanner(banner)` из `src/sections/page-banner/page-banner.njk` — самостоятельная верхняя секция. Принимает `id`, `title`, `image`, `imageAlt`, `breadcrumbsLabel`, `breadcrumbs`; хлебные крошки выводит через общий компонент `breadcrumbs`. Необязательный `mobileImage` подключается через `<source>` в `<picture>`. Изображение заполняет всю ширину и высоту секции через `object-fit: cover`, без смещений и параметров геометрии. Шапка накладывается на секцию при наличии `page.banner`.
- `filters(config)` из `src/components/filters/filters.njk` — группы с произвольными названиями и вариантами. У каждой группы есть уникальный `id`, `title`, `options` и `defaultOpen` (по умолчанию `false`). Значения изначально не выбраны. `option.all: true` обозначает вариант «Все»/«Любой», исключающий конкретные варианты внутри своей группы.
- На мобильном одна и та же форма переносится в нативный `dialog`; состояния сохраняются. Прокручивается весь диалог, закрытие доступно кнопкой, по Escape и нажатием на фон. Аккордеоны анимируются через `grid-template-rows: 0fr / 1fr`; закрытое содержимое имеет `inert`.
- После изменения форма отправляет всплывающее событие `filters:change`, `event.detail.values` содержит объект массивов значений по ID групп. Это точка подключения фильтрации каталога в Битрикс24; демонстрационная статическая выдача сама не фильтруется.
- `pagination(config)` из `src/components/pagination/pagination.njk` принимает `baseUrl`, `currentPage`, `totalPages`, `items` (номера и строка `ellipsis`), подписи и имена иконок стрелок в спрайте. Троеточие — ссылка на первую скрытую страницу после предыдущего номера; `ellipsisLabel` задаёт подпись перехода для `aria-label`. Ссылки используют `?page=N`; клиентский код обновляет активный номер, ссылку троеточия и доступность стрелок из URL, сохраняя остальные параметры. Данные выдачи для страниц подключаются в Битрикс24.

Иконки выводятся через макрос `icon(name, className, width, height)` в `src/components/icon/icon.njk` и SVG-спрайт `src/components/icon-sprite/icon-sprite.njk`. В `filters.assets` и `pagination.assets` передаются имена иконок в спрайте, а не пути к файлам. Для иконок `<img>` не используется.

Цветовая схема выбирается `page.theme: "beige"` или `"dark-blue"` через класс на `body`. Новые компоненты используют БЭМ, собственные SCSS рядом с шаблонами и общие локальные ресурсы.

## Типовая страница услуги

`/service.html` — страница тренажерного зала по макетам 1366 и 360. Статическая сборка находится в `dist/service.html`, данные — в `src/data/pages/service.json`.

Для новой услуги создайте `<slug>.html` в корне проекта с `{% extends "service.njk" %}` и соответствующий JSON в `src/data/pages/<slug>.json`. Общий шаблон `src/templates/service.njk` подключает четыре секции:

- `serviceIntro` — заголовок, описание, хлебные крошки и характеристики услуги.
- `serviceHero` — фотография и информационная карточка. `info.fields` содержит подписи и значения; `info.instructor` — дополнительную информацию с пояснением. Необязательный `mobileImage` выводится через `<source>` в `<picture>`.
- `serviceContent` — вводный текст, массив `features` и фотография. У каждого блока оснащения есть `title`, `items`, необязательные `description` и `wide`.
- `relatedServices` — заголовок, ссылка на каталог и карточки общего компонента `service-card`. Необязательные `desktopOnly` / `mobileOnly` учитывают отличающийся состав карточек в двух макетах.

Секции и информационная карточка находятся в потоке. На desktop фоновые фотография и затемнение позиционируются абсолютно, а карточка и отступы контейнера определяют высоту секции. На мобильном фотография занимает отдельный блок, карточка располагается под ней. Минимальные высоты карточек сохраняют пропорции макета и позволяют блокам расти при увеличении текста. Фотографии заполняют контейнер через `object-fit: cover`, без смещений и увеличения изображения.

Хедер общий для всех страниц: класс `theme-beige` на `body` включает оформление для светлого фона, если хедер не накладывается на баннер. Цвета задаются CSS-переменными `--header-*`, а логотип и SVG-иконки выбираются в существующем шаблоне. Навигация, раскрывающиеся панели и клиентская логика используются без дублирования.

## Детальная страница спецпредложения

`/offer.html` — деталка по макетам 1366 и 360, с формой заявки в нижнем блоке. Данные находятся в `src/data/pages/offer.json`, общий шаблон — `src/templates/offer.njk`. Ссылка на эту деталку добавлена в первую карточку `/offers.html`. Чтобы создать другое предложение, добавьте `<slug>.html` в корне с `{% extends "offer.njk" %}` и соответствующий JSON в `src/data/pages/`.

- `offerIntro` содержит хлебные крошки, здравницу, период действия, заголовок, массив кнопок и фотографию. `actions[].href` задаёт URL бронирования или якорь формы; в демо бронирование открывает письмо на существующий адрес сайта. Иконки «Поделиться» и «Печать» используют общий SVG-спрайт. Поделиться открывает системное меню или копирует ссылку.
- `offerContent.blocks` — последовательность блоков `lead`, `benefits`, `list`, `image`, `html`. Блоки можно добавлять, удалять и переставлять. Тексты растут в потоке, принудительных переносов и фиксированных высот текстовых блоков нет. `html` принимает доверенную разметку редактора CMS; её нужно очищать на сервере перед выводом. Для `image` и верхней фотографии поддерживается `mobileImage` через `<picture>`.
- `offerRequest` содержит ID секции и настройки общего компонента `request-form`: `title`, `description`, `fields`, `hiddenFields`, `consent`, `submitLabel`, `action`. Поля задаются массивом `{ name, type, label, autocomplete, required, minLength, maxLength, pattern }`. В демо оставлено поле Email, как в макете; нижний блок оформлен как заявка по заданию. `offer_id` и `offer_title` передаются скрытыми полями. ID формы/секции должны быть уникальны. Согласие и Email проверяет общий `FormValidator`; без JavaScript работает нативная валидация браузера.
- `relatedOffers.items` использует общий `offer-card` с модификатором `related`. На десктопе — сетка из трёх колонок, до 600px — Swiper со свайпом, клавиатурной навигацией и всеми карточками. При возвращении на десктоп экземпляр Swiper уничтожается, восстанавливая сетку.

Для нативной отправки заполните `offerRequest.form.action` адресом обработчика Битрикс; токен сессии и другие служебные значения можно добавить в `hiddenFields`. Для AJAX-интеграции бэкендер подключает собственный обычный обработчик `submit`. Код проекта отвечает только за валидацию: не отправляет запросы, не блокирует кнопку и не показывает результат отправки. Валидная форма продолжает стандартный `submit`, невалидная блокируется валидатором в фазе захвата. Событие `request-form:submit` и прежняя заготовка отправки удалены. Элемент `[data-request-status]` оставлен для сообщений интеграции.

Сборка создаёт `dist/offer.html` и локальные CSS/JS/изображения, без зависимости от Figma и сервера шаблонов. Для переноса в Битрикс замените Nunjucks-циклы серверными циклами CMS, сохранив БЭМ-классы, имена полей и `data-*` атрибуты. Скрипты и стили можно подключать из статической сборки.



## Валидатор форм и интеграция с Битрикс

Класс `FormValidator` экспортируется из `src/utils/form-validator.ts`; `request-form.ts` автоматически подключает его ко всем `.request-form__form` и предоставляет `window.FormValidator` для обычных скриптов Битрикс. Подключайте скрипт интеграции после выполнения основного JS-модуля сайта (например, следующим `type="module"`-скриптом). Для динамически вставленной формы вызовите `new window.FormValidator(form)`.

```js
const form = document.querySelector('.request-form__form');
const validator = window.FormValidator.getInstance(form);

validator.validate();                    // boolean; ошибки и фокус первого неверного поля
validator.validate({ focus: false });    // проверка без перевода фокуса
validator.validateField(form.elements.namedItem('email'));
validator.setErrors({ email: 'Этот email уже подписан.' }); // ошибки сервера по name
validator.reset();                       // убрать ошибки, сохранить значения
form.reset();                            // нативный сброс значений также убирает ошибки
// validator.destroy();                  // снять обработчики и восстановить noValidate
```

`validate()` нужно вызывать перед AJAX, если отправка запускается напрямую, вне события `submit`. Нативный `form.submit()` обходит обработчики и валидацию; `form.requestSubmit()` запускает проверку. Для полностью ручного подключения создайте экземпляр с `{ validateOnSubmit: false }`; существующий экземпляр предварительно отключите через `destroy()`. Валидатор учитывает `formnovalidate` у кнопки отправки.

Правила задаются HTML-атрибутами: `required`, `type="email"`, `pattern`, `minlength`, `maxlength`, а также нативными ограничениями числовых полей и дат. Обязательный текст из одних пробелов не принимается; выключенные и скрытые поля не проверяются. `type="tel"` сам по себе не проверяет формат — задайте `pattern`. Поля `input`, `select`, `textarea` читаются заново при каждой проверке, поэтому динамически добавленные поля тоже работают.

Сообщения находятся в `src/data/site.json` → `formValidation` и передаются в `data-validation-*` на форме. На отдельном поле можно переопределить сообщение тем же атрибутом, например `data-validation-required` или `data-validation-pattern`. Ошибку выводит элемент внутри формы с `data-validation-error-for="имя поля"`; при изменении `name` в Битрикс меняйте этот атрибут соответственно. Валидатор использует `textContent`, `aria-invalid` и `aria-describedby`; подсказки для чтения с экрана сохраняются. Проверка выполняется при уходе из поля и отправке, показанная ошибка обновляется при вводе. Серверная ошибка сохраняется до редактирования поля или сброса ошибок. Общую ошибку отправки интеграция выводит отдельно в `[data-request-status]`. Проверку на сервере реализует Битрикс.
## Галерея

`/gallery.html` — разводящая страница альбомов по макетам 1366 и 360. Данные находятся в `src/data/pages/gallery.json`, фотографии — в `public/assets/gallery-catalog/`. Карточки с `catalog: true` используют общий `gallery-card` как ссылку; `href` задаёт адрес внутреннего альбома. Карточка «Бассейн» ведёт на `/gallery-pool.html`.

`catalogLayout(navigation, className, label, variant)` из `src/components/catalog-layout/catalog-layout.njk` задаёт общий layout галереи и спецпредложений со sticky-навигацией. Вариант `compact` оставляет больше места сетке галереи. На мобильном общий `resort-navigation` переносит одну и ту же форму в нижнюю панель, сохраняя выбранную категорию; закрытие доступно кнопкой, Escape и нажатием на фон. Компонент отправляет всплывающее событие `resort-navigation:change` с `event.detail.resort`.

Демонстрационные альбомы имеют `resorts: ["all"]` и доступны во всех категориях. Для реального наполнения задайте ID здравниц из `catalog.navigation.items`; общий layout фильтрует элементы с `data-catalog-resorts`. Подпись первого пункта для галереи — «Все фотографии» (в макете сохранилась подпись спецпредложений). Десктопная сетка — CSS Grid из девяти колонок со span 5/4 и 4/5; мобильная — одна колонка с квадратными карточками.

### Внутренний фотоальбом

`/gallery-pool.html` — альбом по макетам 1366 и 360. Данные — `src/data/pages/gallery-pool.json`, секция — `src/sections/gallery-album/`. Фотографии из макета уже находятся в `public/assets/gallery/` и используются повторно. `gallery.title` задаёт название альбома; необязательный `mobileTitle` повторяет отдельный заголовок мобильного макета.

`gallery.items` — упорядоченный массив фотографий `{ image, alt, columns, title?, mobileImage?, modalImage?, mobileModalImage? }`. Поле `columns` задаёт ширину карточки от 1 до 12 колонок, по умолчанию 4; значения за пределами диапазона ограничиваются границами. Например, `"columns": 5` занимает пять колонок. CSS Grid сам размещает карточки в порядке массива и переносит на следующий ряд, когда места недостаточно; позиции и ряды вручную не задаются. В макете используются 5/4/3 и 4/3/5. Высота фотографий — 36.6rem, промежутки — 1rem; на мобильном все карточки занимают одну колонку.

Фотоальбом переиспользует `gallery-card` в варианте `photo` и общий `gallery-modal`. По клику открывается выбранная фотография; доступны стрелки, клавиатура и свайп, закрытие кнопкой, Escape и нажатием на фон. После закрытия фокус возвращается на карточку. Слайдер модалки инициализируется независимо от горизонтальной галереи главной страницы. `modal.id` должен быть уникальным; `title` у фотографии необязателен и выводится только в модалке.

Для нового альбома создайте `<slug>.html` в корне по примеру `gallery-pool.html`, соответствующий JSON в `src/data/pages/` и задайте ссылку на него в карточке `/gallery.html`. Статическая сборка автоматически включает новую HTML-страницу.

## Детальная страница новости

`/news-detail.html` — деталка новости по макетам 1366 и 360. Данные — `src/data/pages/news-detail.json`, общий шаблон — `src/templates/news-detail.njk`. Карточки этой новости на главной и в каталоге ведут на новую страницу.

`newsIntro` задаёт хлебные крошки, заголовок, метаданные, фотографию и подписи кнопок «Поделиться»/«Печать». Фотографии экспортированы из блоков Figma в `public/assets/news-detail/`: 855×404 для десктопа и 336×404 для мобильного. `mobileImage` подключается через `<source>`; высота изображения автоматическая и сохраняет пропорции экспортированного кадра. Кнопка «Поделиться» вызывает системное меню, а при его отсутствии копирует ссылку в буфер; «Печать» открывает печать браузера.

`newsContent.html` содержит доверенный HTML из визуального редактора Битрикс. Внутренние заголовки, абзацы, списки, ссылки и изображения оформляются селекторами обычных тегов внутри `news-content__body`, без БЭМ-классов и отдельных полей для каждого абзаца. При переносе в CMS замените вывод этого поля на `DETAIL_TEXT` новости с типом HTML. Разметка выводится без экранирования и должна поступать из доверенного редактора CMS.

`newsSubscription.form` использует общий `request-form`, как на странице спецпредложения. Для реальной подписки задайте `action` обработчика Битрикс либо подключите собственный обработчик `submit`. Скрытое поле `subscription_type=news` отличает подписку от заявки. Отправку и её результат реализует интеграция Битрикс.

`relatedNews.items` использует существующие `news-card`: три колонки на десктопе и Swiper с карточками шириной 25rem на мобильном. Слайдер создаётся только при ширине до 600px и уничтожается при переходе на десктоп; доступны свайп и стрелки клавиатуры. Секция также поддерживает произвольное число карточек. Сборка создаёт статический `dist/news-detail.html` с локальными CSS и JavaScript.

## Правовая информация

`/legal.html` — каталог документов по макетам 1366 и 360. Данные находятся в `src/data/pages/legal.json`, фотография и разделители — в `public/assets/legal/`. Используются общие шапка, подвал, `page-banner`, `button`, `resort-navigation`, механизм `modal` и фильтрация `catalog-layout`. Для этой страницы добавлены секция `legal-catalog` и повторяемый блок `legal-documents`.

`navigation.links: true` переключает `resort-navigation` на обычные ссылки, а `variant: "horizontal"` располагает их строками на десктопе. `parameter` задаёт URL-параметр выбранной категории (здесь `category`). Ссылки обновляют адрес и активное состояние, фильтруют разделы; работают прямое открытие URL, перезагрузка и история браузера. Внешние ссылки и открытие в новой вкладке сохраняют обычное поведение. На мобильном тот же список переносится в существующую нижнюю модалку; выбор закрывает окно. Радионавигация прежних каталогов остаётся стандартным вариантом компонента. Необязательный `item.labelLines` задаёт переносы подписей только на мобильном.

`catalog.groups` содержит заголовки и документы `{ title, href }`; `titleLines` позволяет задать переносы заголовка из макета. Документ о правилах нахождения на территории ведёт на `/legal-detail.html`; остальные адреса «Подробнее» — заготовки будущих детальных страниц `/legal/<slug>/`, их нужно заменить адресами документов или страниц Битрикс при подключении контента. Ссылка «Правовая информация» в общей навигации ведёт на новый каталог. Сборка создаёт статический `dist/legal.html`.

## Часто задаваемые вопросы

`/faq.html` — страница FAQ по макетам 1366 и 360. Данные находятся в `src/data/pages/faq.json`, секция — в `src/sections/faq/`, повторяемый компонент — в `src/components/accordion/`. Переиспользуются общие шапка, подвал, `page-banner`, `breadcrumbs` и `icon`. Фото и SVG экспортированы из Figma в `public/assets/faq/`; иконки подключены через общий спрайт. `bodyClass: "page-faq"` задаёт фон этой страницы внутри бежевой схемы, `banner.mobileTitleLines` — переносы заголовка на мобильном.

`accordion(item)` принимает уникальный `id`, `question`, массив абзацев `answer`, необязательные `mobileQuestionLines` и `defaultOpen` (по умолчанию `false`). Все вопросы FAQ изначально закрыты и раскрываются независимо. Переход между `grid-template-rows: 0fr / 1fr` анимирует содержимое без измерения высоты в JavaScript; кнопка обновляет `aria-expanded`, закрытая панель получает `inert`. Enter и Space работают через нативную кнопку, при `prefers-reduced-motion` анимация отключается. Пока все ответы содержат один демонстрационный текст из макета; перед подключением Битрикс замените `faq.items[].answer` рабочими текстами. Сборка создаёт статический `dist/faq.html`.

## Пустой результат поиска

`/search-empty.html` — состояние «по вашему запросу ничего не найдено» по макетам 1366 и 360. Данные находятся в `src/data/pages/search-empty.json`, сообщение и стили — в `src/sections/search-empty/`. Страница переиспользует секцию `search` и ту же форму `search-form`, что `/search.html`: параметр `?q=` подставляется в поле, повторная отправка ведёт на `/search-results.html`. Без параметра показан запрос «Уникальный» на обоих экранах; мобильный макет содержит пустое поле, но введённый запрос сохраняется независимо от ширины экрана. Реальная поисковая выдача подключается при переносе в Битрикс; эта страница служит статическим шаблоном пустого состояния. Сборка автоматически создаёт `dist/search-empty.html`.
