# Veora — базовая сборка многостраничного сайта

Vite собирает отдельные HTML-страницы, TypeScript и SCSS. Nunjucks даёт страницам наследовать общий layout через `extends` и переопределять его блоки. Шрифт Inter поставляется локально через Fontsource и входит в сборку без запросов к Google Fonts. Результат — статические файлы, которые можно подготовить к переносу в сайты Битрикс24.

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес, который выведет Vite. Готовую сборку создаёт `npm run build` в папке `dist/`. Для её локального просмотра — `npm run preview`.

## Структура

- `index.html` — главная страница.
- `about/index.html` — пример внутренней страницы.
- `src/templates/layout.njk` — общий HTML-каркас с блоком `content`.
- `src/components/` — переиспользуемые БЭМ-компоненты; у каждого свой `.njk` и `.scss`.
- `src/sections/` — секции страниц как самостоятельные БЭМ-блоки; у каждой свой `.njk` и `.scss`.
- `src/data/site.json` — общие данные сайта; `src/data/pages/` — данные отдельных страниц.
- `src/styles/main.scss` — точка подключения SCSS компонентов и секций; `_base.scss` и `_tokens.scss` — базовые стили и переменные.
- `src/main.ts` — клиентский TypeScript.
- `vite.config.mjs` — поиск HTML-страниц, подключение шаблонов и загрузка JSON-данных.
- `AGENTS.md` — правила вёрстки, включая `1rem = 10px` и медиавыражения в пикселях.

## Новая страница

Создайте `contacts.html` в корне проекта рядом с `index.html` с наследованием layout и подключением секции:

```html
{% extends "layout.njk" %}
{% block content %}
  {% include "sections/contacts/contacts.njk" %}
{% endblock %}
```

Создайте данные `src/data/pages/contacts.json` с `title`, `description`, `activePage` и данными секции. Добавьте секцию в `src/sections/contacts/` с файлами `contacts.njk` и `_contacts.scss`; подключите SCSS в `src/styles/main.scss`. Для ссылки в навигации дополните `src/data/site.json`.

Страница будет доступна по `/contacts.html` и автоматически попадёт в `dist/contacts.html`. Путь к JSON повторяет путь к HTML-странице внутри `src/data/pages/`.

Файлы из `public/` (если папка нужна) Vite копирует в сборку без обработки. Импортируемые из TypeScript и SCSS ресурсы Vite обрабатывает и хеширует.

## Страница услуг

`/services.html` — каталог по desktop-макету 1366 и мобильному макету 360. Данные находятся в `src/data/pages/services.json`. В сборке страница доступна в `dist/services.html`.

- `breadcrumbs(items, label)` из `src/components/breadcrumbs/breadcrumbs.njk` — самостоятельный БЭМ-блок хлебных крошек без дополнительных классов секций. Принимает массив `{ label, href? }` и название навигации для `aria-label`. Элемент без `href` обозначает текущую страницу; пустой массив не выводит навигацию. Цвет наследуется от окружения.
- `pageBanner(banner)` из `src/sections/page-banner/page-banner.njk` — самостоятельная верхняя секция. Принимает `id`, `title`, `image`, `imageAlt`, `breadcrumbsLabel`, `breadcrumbs`; хлебные крошки выводит через общий компонент `breadcrumbs`. Необязательный `mobileImage` подключается через `<source>` в `<picture>`. Изображение заполняет всю ширину и высоту секции через `object-fit: cover`, без смещений и параметров геометрии. Шапка накладывается на секцию при наличии `page.banner`.
- `filters(config)` из `src/components/filters/filters.njk` — группы с произвольными названиями и вариантами. У каждой группы есть уникальный `id`, `title`, `options` и `defaultOpen` (по умолчанию `false`). Значения изначально не выбраны. `option.all: true` обозначает вариант «Все»/«Любой», исключающий конкретные варианты внутри своей группы.
- На мобильном одна и та же форма переносится в нативный `dialog`; состояния сохраняются. Прокручивается весь диалог, закрытие доступно кнопкой, по Escape и нажатием на фон. Аккордеоны анимируются через `grid-template-rows: 0fr / 1fr`; закрытое содержимое имеет `inert`.
- После изменения форма отправляет всплывающее событие `filters:change`, `event.detail.values` содержит объект массивов значений по ID групп. Это точка подключения фильтрации каталога в Битрикс24; демонстрационная статическая выдача сама не фильтруется.
- `pagination(config)` из `src/components/pagination/pagination.njk` принимает `baseUrl`, `currentPage`, `totalPages`, `items` (номера и строка `ellipsis`), подписи и имена иконок стрелок в спрайте. Троеточие — ссылка на первую скрытую страницу после предыдущего номера; `ellipsisLabel` задаёт подпись перехода для `aria-label`. Ссылки используют `?page=N`; клиентский код обновляет активный номер, ссылку троеточия и доступность стрелок из URL, сохраняя остальные параметры. Данные выдачи для страниц подключаются в Битрикс24.

Иконки выводятся через макрос `icon(name, className, width, height)` в `src/components/icon/icon.njk` и SVG-спрайт `src/components/icon-sprite/icon-sprite.njk`. В `filters.assets` и `pagination.assets` передаются имена иконок в спрайте, а не пути к файлам. Для иконок `<img>` не используется.

Цветовая схема выбирается `page.theme: "beige"` или `"dark-blue"` через класс на `body`. Новые компоненты используют БЭМ, собственные SCSS рядом с шаблонами и общие локальные ресурсы.

## Типовая страница услуги

`/service.html` — страница тренажерного зала по макетам 1366 и 360. Статическая сборка находится в `dist/service.html`, данные — в `src/data/pages/service.json`.

Для новой услуги создайте `<slug>.html` в корне проекта с `{% extends "service.njk" %}` и соответствующий JSON в `src/data/pages/<slug>.json`. Общий шаблон `src/templates/service.njk` подключает четыре секции:

- `serviceIntro` — заголовок, описание, хлебные крошки и характеристики услуги.
- `serviceHero` — фотография и информационная карточка. `info.fields` содержит подписи и значения; `info.instructor` — дополнительную информацию с пояснением. Необязательный `mobileImage` выводится через `<source>` в `<picture>`.
- `serviceContent` — вводный текст, массив `features` и фотография. У каждого блока оснащения есть `title`, `items`, необязательные `description` и `wide`.
- `relatedServices` — заголовок, ссылка на каталог и карточки общего компонента `service-card`. Необязательные `desktopOnly` / `mobileOnly` учитывают отличающийся состав карточек в двух макетах.

Секции и информационная карточка находятся в потоке. На desktop фоновые фотография и затемнение позиционируются абсолютно, а карточка и отступы контейнера определяют высоту секции. На мобильном фотография занимает отдельный блок, карточка располагается под ней. Минимальные высоты карточек сохраняют пропорции макета и позволяют блокам расти при увеличении текста. Фотографии заполняют контейнер через `object-fit: cover`, без смещений и увеличения изображения.

Хедер общий для всех страниц: класс `theme-beige` на `body` включает оформление для светлого фона, если хедер не накладывается на баннер. Цвета задаются CSS-переменными `--header-*`, а логотип и SVG-иконки выбираются в существующем шаблоне. Навигация, раскрывающиеся панели и клиентская логика используются без дублирования.

## Детальная страница спецпредложения

`/offer.html` — деталка по макетам 1366 и 360, с формой заявки в нижнем блоке. Данные находятся в `src/data/pages/offer.json`, общий шаблон — `src/templates/offer.njk`. Ссылка на эту деталку добавлена в первую карточку `/offers.html`. Чтобы создать другое предложение, добавьте `<slug>.html` в корне с `{% extends "offer.njk" %}` и соответствующий JSON в `src/data/pages/`.

- `offerIntro` содержит хлебные крошки, здравницу, период действия, заголовок, массив кнопок и фотографию. `actions[].href` задаёт URL бронирования или якорь формы; в демо бронирование открывает письмо на существующий адрес сайта. Иконки «Поделиться» и «Печать» используют общий SVG-спрайт. Поделиться открывает системное меню или копирует ссылку.
- `offerContent.blocks` — последовательность блоков `lead`, `benefits`, `list`, `image`, `html`. Блоки можно добавлять, удалять и переставлять. Тексты растут в потоке, принудительных переносов и фиксированных высот текстовых блоков нет. `html` принимает доверенную разметку редактора CMS; её нужно очищать на сервере перед выводом. Для `image` и верхней фотографии поддерживается `mobileImage` через `<picture>`.
- `offerRequest` содержит ID секции и настройки общего компонента `request-form`: `title`, `description`, `fields`, `hiddenFields`, `consent`, `submitLabel`, `action`, сообщения результата. Поля задаются массивом `{ name, type, label, autocomplete, required, maxLength }`. В демо оставлено поле Email, как в макете; нижний блок оформлен как заявка по заданию. `offer_id` и `offer_title` передаются скрытыми полями. ID формы/секции должны быть уникальны. Согласие и Email проверяются нативной валидацией браузера.
- `relatedOffers.items` использует общий `offer-card` с модификатором `related`. На десктопе — сетка из трёх колонок, до 600px — Swiper со свайпом, клавиатурной навигацией и всеми карточками. При возвращении на десктоп экземпляр Swiper уничтожается, восстанавливая сетку.

Для нативной отправки заполните `offerRequest.form.action` адресом обработчика Битрикс. Компонент отправит обычный POST; токен сессии и другие служебные значения можно добавить в `hiddenFields`. Для AJAX-интеграции обработчик слушает всплывающее отменяемое событие `request-form:submit`, вызывает `event.preventDefault()` и получает `event.detail` с `form`, `formData`, `resolve(message?)`, `reject(message?)`. Кнопка блокируется до вызова одной из этих функций. Вызывайте `resolve` только после подтверждённого успеха сервера; она сбрасывает форму и показывает сообщение. `reject` сохраняет введённые данные и показывает ошибку. Если `action` и обработчик не настроены, демо показывает сообщение о недоступности отправки и не имитирует сохранение заявки.

Сборка создаёт `dist/offer.html` и локальные CSS/JS/изображения, без зависимости от Figma и сервера шаблонов. Для переноса в Битрикс замените Nunjucks-циклы серверными циклами CMS, сохранив БЭМ-классы, имена полей и `data-*` атрибуты. Скрипты и стили можно подключать из статической сборки.
